# Contributor Tasks

Choose a bounded contribution below. Work in a branch of the public companion; follow its [contribution guide](https://github.com/sakti1977/Harness-Engineering/blob/main/CONTRIBUTING.md). These are suggested tasks, not assigned issues. Report commands, versions and observed results; do not include credentials or production records.

## Fix one confusing starter step

Try [[Adopt One Outcome - Walkthrough]] without maintainer help. Record the first confusing instruction, your platform and the command/output. Propose a small wording or command change. Acceptance: another reader can complete that step; commands and links still work; expected failures remain clearly distinguished from errors.

## Add one missed failure and its clean counterpart

Choose a domain invariant outside duplicate booking. Submit a minimal defective fixture, fixed fixture and an assertion at the relevant boundary. Acceptance: the defect fails for the intended reason; the fix passes; no network or model key is required for the deterministic demonstration. Explain limits. Public-kit gates also require its harness-test manifest entries.

## Correct one source-backed claim

Choose one note and identify the precise claim, original source and version/date. Acceptance: the source directly supports the revised claim, interpretation is labeled, and third-party text is not copied wholesale. Follow [[Source Note Template]].

## Report one adoption result

Use a disposable copy of an existing project. Record outcome, selected control, setup time, first useful result, false alarms and whether you would reuse it. Acceptance: facts and opinions are separate; failures and maintainer assistance are included; project details are shared only with permission. One report does not establish general effectiveness.

## Add one reference stack

Propose a minimal TypeScript API or another maintained stack before expanding dependencies. Acceptance: documented runtime/version, one command to reproduce a defect, outcome checks through the API and persistence boundary, a passing fix, and an identified maintenance owner. This task remains unimplemented in the vault.

Edit canonical learning content in the companion's `vault/` and regenerate its handbook. Do not independently edit the generated copy. See [[Companion Version and Sync]] for this working vault's relationship to the public kit.
