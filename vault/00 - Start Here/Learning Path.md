# Learning Path

Choose a route by what you need to do. The milestones below are observable outcomes, not reading quotas.

## Learn the foundations

1. Read [[Five Layers of a Harness]] and [[Agent Harness and Evaluation Harness]]. **Milestone:** classify a tool permission, environment probe and final-state assertion correctly.
2. Read [[False Passing Feature]] and run [[First Executable Harness Lab]]. **Milestone:** explain why the weak check passes and the outcome checks fail.
3. Read [[Source Register]] and [[Case Studies - MOC]]. **Milestone:** distinguish a sourced claim, instructional scenario and executed local result.

## Improve an existing project

1. Follow [[Project Harness Assessment]] and [[Recovery Audit]]. **Milestone:** identify one observed failure and the control that owns it.
2. Fill [[Task Contract Template]], then read [[Authority Policy]] and [[Readiness Contract]]. **Milestone:** record the change boundary and a reviewed verification command.
3. Use [[Claim-to-Proof Matrix]] and [[Failure to Evaluation Workflow]]. **Milestone:** produce a regression that fails on the defect and passes on the fix.
4. Write [[Cold-Session Checkpoint]]. **Milestone:** another reader can recover the state and next action from durable artifacts.

## Build or evaluate a runtime

1. Study [[Agent Runtime - MOC]] and [[Tools and Interfaces - MOC]]. **Milestone:** explain stop reasons, retry identities and tool validation boundaries.
2. Study [[Sandbox Enforcement Matrix]] and [[MCP Identity and Network Boundaries]]. **Milestone:** identify what is documented, configured, exercised and actually enforced.
3. Use [[Agent Evaluation Suite]], [[Grader Reliability]] and [[Experiment Template]]. **Milestone:** specify a reproducible comparison before paying for live runs.
4. Study [[Harness Ablation Experiments]] and [[Repository Pattern Atlas]]. **Milestone:** justify keeping or removing one mechanism from evidence, including cost and regressions.

## Maintain the knowledge base

Use [[Knowledge Base Maintenance]] and [[Templates - MOC]]. A new topic should have a concrete failure, primary source, exercise and limitations. See [[Harness Improvement Roadmap]] for pending product work and [[Vault Update Record]] for completed local evidence.
