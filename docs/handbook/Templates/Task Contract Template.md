# Task contract

- Outcome: reject a conflicting booking while allowing a different slot.
- Expected surface: booking implementation and its tests.
- Exclusions: authentication, deployment and timezone redesign.
- Claims: conflict result; no new row on rejection; valid request persists.
- Verification: explicit reviewed test command, initial fixture and expected observations.
- Authority: disposable test data only; no production credentials or network writes.
- Budget: choose a time/cost limit and reserve verification time before execution.
- Ownership: one editor per output file; an integration owner checks results.
- Discovery rule: record unrelated improvements; amend scope for necessary dependencies.
- Handoff: revision, changed files, commands/results, unresolved effects and next action.

This is a filled teaching example. Replace its outcome and claims for your project. See [Scope Contract](../05%20-%20Scope/Scope%20Contract.md) and [Claim-to-Proof Matrix](../06%20-%20Verdict/Claim-to-Proof%20Matrix.md).
