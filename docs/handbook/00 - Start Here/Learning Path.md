# Learning Path

Choose a route by what you need to do. The milestones below are observable outcomes, not reading quotas.

## Learn the foundations

1. Read [Five Layers of a Harness](../01%20-%20Foundations/Five%20Layers%20of%20a%20Harness.md) and [Agent Harness and Evaluation Harness](../01%20-%20Foundations/Agent%20Harness%20and%20Evaluation%20Harness.md). **Milestone:** classify a tool permission, environment probe and final-state assertion correctly.
2. Read [False Passing Feature](../12%20-%20Case%20Studies/False%20Passing%20Feature.md) and run [First Executable Harness Lab](../11%20-%20Practical%20Implementations/First%20Executable%20Harness%20Lab.md). **Milestone:** explain why the weak check passes and the outcome checks fail.
3. Read [Source Register](Source%20Register.md) and [Case Studies - MOC](../12%20-%20Case%20Studies/Case%20Studies%20-%20MOC.md). **Milestone:** distinguish a sourced claim, instructional scenario and executed local result.

## Improve an existing project

1. Follow [Project Harness Assessment](../11%20-%20Practical%20Implementations/Project%20Harness%20Assessment.md) and [Recovery Audit](../02%20-%20Reach/Recovery%20Audit.md). **Milestone:** identify one observed failure and the control that owns it.
2. Fill [Task Contract Template](../Templates/Task%20Contract%20Template.md), then read [Authority Policy](../03%20-%20Power/Authority%20Policy.md) and [Readiness Contract](../04%20-%20Ground/Readiness%20Contract.md). **Milestone:** record the change boundary and a reviewed verification command.
3. Use [Claim-to-Proof Matrix](../06%20-%20Verdict/Claim-to-Proof%20Matrix.md) and [Failure to Evaluation Workflow](../10%20-%20Harness%20Testing/Failure%20to%20Evaluation%20Workflow.md). **Milestone:** produce a regression that fails on the defect and passes on the fix.
4. Write [Cold-Session Checkpoint](../07%20-%20Carry/Cold-Session%20Checkpoint.md). **Milestone:** another reader can recover the state and next action from durable artifacts.

## Build or evaluate a runtime

1. Study [Agent Runtime - MOC](../08%20-%20Agent%20Runtime/Agent%20Runtime%20-%20MOC.md) and [Tools and Interfaces - MOC](../09%20-%20Tools%20and%20Interfaces/Tools%20and%20Interfaces%20-%20MOC.md). **Milestone:** explain stop reasons, retry identities and tool validation boundaries.
2. Study [Sandbox Enforcement Matrix](../03%20-%20Power/Sandbox%20Enforcement%20Matrix.md) and [MCP Identity and Network Boundaries](../03%20-%20Power/MCP%20Identity%20and%20Network%20Boundaries.md). **Milestone:** identify what is documented, configured, exercised and actually enforced.
3. Use [Agent Evaluation Suite](../10%20-%20Harness%20Testing/Agent%20Evaluation%20Suite.md), [Grader Reliability](../10%20-%20Harness%20Testing/Grader%20Reliability.md) and [Experiment Template](../Templates/Experiment%20Template.md). **Milestone:** specify a reproducible comparison before paying for live runs.
4. Study [Harness Ablation Experiments](../10%20-%20Harness%20Testing/Harness%20Ablation%20Experiments.md) and [Repository Pattern Atlas](../13%20-%20Research/Repository%20Pattern%20Atlas.md). **Milestone:** justify keeping or removing one mechanism from evidence, including cost and regressions.

## Maintain the knowledge base

Use [Knowledge Base Maintenance](../02%20-%20Reach/Knowledge%20Base%20Maintenance.md) and [Templates - MOC](../Templates/Templates%20-%20MOC.md). A new topic should have a concrete failure, primary source, exercise and limitations. See [Harness Improvement Roadmap](Harness%20Improvement%20Roadmap.md) for pending product work and [Vault Update Record](Vault%20Update%20Record.md) for completed local evidence.
